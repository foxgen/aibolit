# Как устроен Aibolit

Три независимые части: **Copy instructions** собирает инструкции для ИИ,
файловый протокол `version: 2` через **Apply context** изменяет файлы,
а протокол `version: 3` через ту же команду запускает подтверждённые скрипты
и сохраняет результаты.

## Файлы по назначению

| Файл | Ответственность |
| --- | --- |
| `extension.js` | Команды VS Code и сообщения пользователю |
| `src/protocol.js` | JSON из буфера: формат, версия, лимит количества действий |
| `src/instructions.js` | Хранение Base/Custom/Project, сброс и резервные копии |
| `src/engine.js` | Подготовка всех изменений в памяти, без записи на диск |
| `src/file-access.js` | Безопасные пути, проверка корня, UTF-8 и размера файлов |
| `src/actions/index.js` | Реестр разрешённых файловых действий |
| `src/actions/create-file.js` | Логика `createFile` |
| `src/actions/patch.js` | Логика `patch` и `applyPatch` |
| `src/transaction.js` | Запись подготовленных файлов и восстановление при сбоях |
| `src/scripts/request.js` | Проверка JSON-запросов скриптов |
| `src/scripts/execution.js` | Подтверждения перед каждым запуском и статусы цепочки |
| `src/scripts/preview.js` | Предпросмотр через виртуальную файловую систему только для чтения |
| `src/scripts/runner.js` | Запуск интерпретаторов и лимиты исполнения |
| `src/scripts/storage.js` | Скрипты, разрешения и результаты выполнений |
| `src/scripts/outputs.js` | Копирование и удаление результатов |

## Уровни инструкций

`combinedInstructions(storageDir, templateFile, projectRoot)` собирает три уровня
правил. `projectRoot` необязателен; в многокорневом workspace пользователь
явно выбирает папку. `ensureProjectInstructions()` создаёт
`.aibolit/instructions.md` только при редактировании.

`resetInstructions({ type, storageDir, templateFile, projectRoot })` поддерживает
`base`, `custom` и `project`. Перед записью делает резервную копию в
`globalStorageUri/backups/`; Base восстанавливается из шаблона текущей версии,
Custom очищается, Project удаляет файл и по возможности пустую папку `.aibolit` (не создавая отсутствующие). Подтверждение и проверка несохранённых изменений
выполняются в `extension.js`.

## Как проходит Apply context

1. `parseContext()` проверяет JSON-пакет.
2. `prepare()` проходит действия по порядку, выбирая обработчик из реестра.
3. Обработчики меняют **только содержимое в памяти** (`Buffer` или `null`).
4. После успешного `prepare()` функция `commit()` проверяет файлы и записывает их.
5. При сбое записи `commit()` пытается вернуть исходное содержимое. Истории Undo нет.

## Как добавить новое файловое действие

1. Создайте `src/actions/<name>.js` с функцией `apply(action, current, display, number)`.
2. `current` — `Buffer` с текущими данными либо `null` для отсутствующего файла.
3. Функция должна **проверить входные данные** и вернуть новый `Buffer`, но **не писать на диск**.
4. Зарегистрируйте обработчик в `src/actions/index.js`.
5. Обновите `prompts/protocol.md`, пример использования и тесты для успешного и ошибочного случаев.
6. Если изменился формат JSON, отдельно обновите `src/protocol.js` и версию протокола.

Образец: `src/actions/create-file.js` — минимальный обработчик.

**Важно:** консольные команды, запускающие произвольный код, нельзя добавлять
как обычный файловый обработчик: транзакция не умеет отменять побочные эффекты
скриптов. Для них уже существует **отдельный** механизм `src/scripts/`.

## Проверка

```powershell
npm install
npm run check
npm test
npm run build
```

Изменение существующих JS-модулей должно сохранять публичный API `src/engine.js`
(`prepare`, `commit`, `relativeSegments`, константы лимитов).

> Полная атомарность при аварийном завершении процесса или ОС не гарантируется.
> Используйте Git и проверяйте результат через `git diff`.

## Выполнение скриптов (протокол v3, Aibolit 0.3.4)

Механизм исполнения вынесен в `src/scripts/`:

- `preview.js` — регистрирует виртуальную файловую систему с `isReadonly: true` и `FilePermission.Readonly`; вкладка показывает исходный код, аргументы и рабочий каталог, не разрешая запись; после открытия подтверждение немодальное.
- `request.js` — проверяет JSON `version:3, kind:script`, ограничения и идентификаторы.
- `execution.js` — разрешения, последовательное исполнение, сводка `result.json`, пропуск оставшихся команд после ошибки.
- `runner.js` — запуск интерпретатора без shell через `spawn`, перехват stdout/stderr, лимиты.
- `storage.js` — сохранённые скрипты, версии по SHA-256, запросы и отдельные каталоги запусков.
- `outputs.js` — подготовка JSON для ИИ, копирование и ручная очистка только `runs/`.

Файловая транзакция v2 не выполняет скрипты. При добавлении нового языка нужно обновить `src/scripts/request.js`, `src/scripts/runner.js`, разрешённые настройки `package.json`, шаблон `prompts/protocol.md` и тесты. Запуск скриптов не атомарен и не ограничен правами проекта: требуется явное разрешение, полноценная песочница пока отсутствует.
