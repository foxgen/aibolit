# Aibolit — AI Context for VS Code

**Aibolit 0.3.5** — расширение VS Code для работы с ИИ через буфер обмена. Оно передаёт ИИ инструкции и исходный код, применяет предложенные изменения файлов, запускает подтверждённые пользователем скрипты и возвращает результаты команд в чат.

Aibolit не требует API-ключа или подключения к какому-либо сервису ИИ: пользователь сам переносит текст между VS Code и чатом. Расширение работает в обычных папках VS Code, в том числе в окне **Remote SSH**, где скрипты исполняются на удалённой машине.

> **Безопасность.** Скрипты запускаются с правами пользователя, **без песочницы** и без автоматического отката. Перед запуском просмотрите код, рабочий каталог и аргументы. Не передавайте ИИ секреты из файлов и вывода команд.

## Начало работы

1. Откройте проект в VS Code и убедитесь, что workspace отмечен как **Trusted**.
2. Выберите **Aibolit → Copy instructions** и вставьте содержимое буфера обмена в чат с ИИ. Это сообщает ИИ доступные операции, форматы JSON и правила безопасности.
3. Опишите задачу. Если ИИ нужны исходники, используйте **Aibolit → Copy code** для нужных файлов или выполните диагностический запрос скрипта, который он подготовит.
4. Скопируйте **один JSON-объект**, предложенный ИИ, в буфер обмена и выберите **Aibolit → Apply context**.
5. Для скриптов изучите предпросмотр и подтвердите каждый новый или изменённый запуск. Aibolit выполнит команды по очереди и **автоматически скопирует итоговый JSON в буфер**. Вставьте его в чат, чтобы ИИ получил реальные результаты.

При изменении файлов результат отображается в уведомлении VS Code. Рекомендуется проверять изменения через Git (`git diff`) и запускать тесты проекта.

## Меню

Действия доступны через **Aibolit** в контекстном меню проводника и редактора VS Code.

| Команда | Назначение |
| --- | --- |
| **Copy instructions** | Копирует правила Aibolit для нового диалога с ИИ: Base + необязательные Custom и Project |
| **Copy code** | Копирует содержимое выбранных файлов с путями относительно проекта |
| **Apply context** | Применяет JSON с файловыми действиями или запросом исполнения скриптов |
| **Output → Copy...** | Повторно копирует последний или несколько сохранённых результатов выполнения |
| **Output → Delete...** | Удаляет выбранные результаты или всю историю выполнений, но сохраняет библиотеку скриптов |
| **Edit instructions...** | Редактирует или сбрасывает базовые, пользовательские и проектные правила |

### Инструкции для ИИ

Базовый шаблон: [`prompts/protocol.md`](prompts/protocol.md). Он рассчитан на **новый диалог без предыдущего контекста**: в нём описаны действия, поля запросов, ограничения, результаты и поведение при ошибках.

Итоговая команда **Copy instructions** объединяет три уровня:

- **Base** — технический протокол Aibolit. Личная копия хранится в `ExtensionContext.globalStorageUri` VS Code.
- **Custom** — дополнительные правила пользователя, там же; по умолчанию пустые.
- **Project** — правила отдельного проекта в `.aibolit/instructions.md`, если файл существует.

Базовая копия создаётся при первом использовании и **не заменяется автоматически** файлом из исходников. Чтобы синхронизировать её с шаблоном установленного расширения, выберите **Edit instructions... → Reset instructions... → Base**. Перед сбросом создаётся резервная копия; Custom и Project сохраняются. Для проекта с несколькими корнями Aibolit предложит выбрать папку, правила которой нужно включить.

## Запросы JSON

Команда **Apply context** принимает **один валидный JSON-объект** из буфера обмена; допускается один Markdown-блок `json` без пояснений вокруг. Все сообщения используют **`"version": 1`**; `kind` указывает тип. Aibolit принимает запросы `actions` и `script`, а выдаёт ответы `result` и `results`. Номер протокола независим от номера релиза расширения.

### Изменение файлов — `kind: "actions"`

```json
{
  "version": 1,
  "kind": "actions",
  "actions": [
    {
      "type": "createFile",
      "path": "notes/hello.txt",
      "content": "Hello from Aibolit!\n"
    }
  ]
}
```

Поддерживаются `createFile` (создание отсутствующего файла) и `patch` (unified diff для существующего файла). До записи проверяются все действия; при сбое записи Aibolit **пытается** восстановить исходное состояние. Полной транзакционной гарантии и команды Undo нет. Нельзя удалять, переименовывать или изменять файлы произвольной командой JSON. Для патчей ИИ нужны актуальные исходники, полученные через Copy code или диагностический скрипт.

### Выполнение скриптов — `kind: "script"`

```json
{
  "version": 1,
  "kind": "script",
  "requestId": "inspect-project-001",
  "commands": [
    {
      "id": "environment",
      "script": {
        "id": "inspect-environment",
        "language": "python",
        "content": "import platform\nprint('OS:', platform.system())\nprint('Python:', platform.python_version())\n"
      }
    },
    {
      "id": "project-files",
      "script": {
        "id": "inspect-project-files",
        "language": "python",
        "content": "from pathlib import Path\nfor p in sorted(Path('.').iterdir()):\n    print(('DIR ' if p.is_dir() else 'FILE ') + p.name)\n"
      }
    }
  ]
}
```

Поддерживаемые языки: `python`, `bash`, `powershell`. По умолчанию Aibolit ищет команды `python`, `bash` и `pwsh` соответственно. Путь к интерпретатору настраивается через `aibolit.scripts.pythonCommand`, `aibolit.scripts.bashCommand` и `aibolit.scripts.powershellCommand`. Например, на Linux должна существовать команда `python`, даже если установлен только `python3` (либо настройте соответствующий интерпретатор в VS Code).

Каждая команда запускается в каталоге корня проекта. В окне **Remote SSH** это каталог проекта **на удалённом хосте**; интерпретатор тоже должен быть доступен на удалённом хосте. Для workspace с несколькими корнями запрос должен содержать поле `"root": "точное имя корня"` на верхнем уровне.

Скрипты выполняются последовательно. Подтверждение запрашивается непосредственно перед запуском, если соответствующее сочетание кода, каталога и аргументов ещё не разрешено. **View script** открывает код и параметры запуска во вкладке **только для чтения**. При ошибке или отказе следующие команды получают `skipped`, не запускаются и не записываются в библиотеку скриптов.

После выполнения Aibolit копирует в буфер JSON `{"version":1,"kind":"result",...}` с общим `status`, `executionId` и результатом каждого шага (`status`, `exitCode`, `stdout`, `stderr`). При копировании нескольких запусков через Output → Copy... используется `kind: "results"` с массивом `executions`. Эти сообщения — **ответы для ИИ**, их нельзя отправлять обратно в **Apply context**.

Полный контракт сообщений, в том числе повторные вызовы по `scriptId`, аргументы, лимиты и обработка ошибок, находится в [`prompts/protocol.md`](prompts/protocol.md).

## История и хранение данных

Скрипты, разрешения и запуски сохраняются в рабочем хранилище VS Code (`ExtensionContext.storageUri`) отдельно для каждого workspace:

```text
scripts/                         # библиотека скриптов и разрешения
runs/exec-<uuid>/
  request.json                   # исходный JSON-запрос
  result.json                    # метаданные выполнения и статусы
  commands/<id>/stdout.log
  commands/<id>/stderr.log
```

Лимиты: **60 секунд** и **2 МиБ stdout+stderr** на команду, **50 МиБ** на историю, **64 КиБ** на копируемый результат. При заполнении истории её нужно очистить вручную через **Output → Delete...**; сохранённые скрипты при этом остаются. Исходные запросы сохраняются в истории в том числе при ошибках, поэтому **не включайте в них секреты**.

Файловые действия и выполнение скриптов — разные механизмы: скрипты могут изменять файлы вне проекта и их побочные эффекты не откатываются.

## Установка из исходников

Нужны VS Code, Node.js и npm. Откройте терминал в корне проекта:

```bash
npm install
npm run check
npm test
npm run build
```

Сборка создаёт файл `aibolit-0.3.5.vsix`. Установите его на машине, где работает VS Code, например на Windows:

```powershell
code --install-extension .\aibolit-0.3.5.vsix --force
```

Затем выполните **Developer: Reload Window**. В PowerShell при ограничениях на выполнение `npm.ps1` используйте `npm.cmd`. Для окна Remote SSH проверьте, что расширение запущено в нужной среде VS Code и интерпретаторы доступны там, где исполняются команды.
