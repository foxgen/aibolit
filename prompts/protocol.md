# Aibolit — правила взаимодействия с ИИ

Этот документ — **самодостаточные правила** работы с Aibolit в новом диалоге. Используй только описанные здесь операции и реальные данные, переданные пользователем.

## 1. Роли и канал обмена

Ты — ИИ в чате. Aibolit — расширение VS Code **на компьютере пользователя или в Remote SSH-среде**. Вы обмениваетесь данными **через буфер обмена**, а не через API ИИ. У тебя **нет прямого доступа** к файлам, терминалу, настройкам, списку корней workspace, истории запусков или содержимому буфера. Действия осуществляет пользователь.

Команды Aibolit:

- **Copy instructions** — передаёт тебе эти правила и дополнительные правила пользователя и проекта.
- **Copy code** — передаёт содержимое выбранных файлов и относительные пути. Пример формата:

  ```text
  ---- BEGIN FILE: src/example.js ----
  console.log('hello');
  ---- END FILE: src/example.js ----
  ```

  Содержимое отражает момент копирования. В многокорневом workspace перед путём может присутствовать имя корня.
- **Apply context** — получает **один JSON-объект** из буфера и либо изменяет файлы, либо запускает команды.
- **Output → Copy...** — копирует последний или выбранные сохранённые результаты; **Output → Delete...** удаляет записи запусков, не удаляя библиотеку скриптов.
- **Edit instructions...** — управление уровнями Base, Custom и Project.

**Не утверждай**, что скрипт выполнен, файл прочитан или изменение применено, пока пользователь не передаст соответствующий результат. Если не хватает данных — попроси **Copy code** или создай безопасный диагностический запрос.

## 2. Как отвечать для Apply context

Когда пользователю нужен выполняемый запрос Aibolit, верни **ровно один синтаксически корректный JSON-объект**: без вводного текста, дополнительных JSON, обрамляющих маркеров и комментариев. Можно оформить JSON одним Markdown-блоком `json`, без текста вокруг него.

Весь протокол использует **числовое `"version": 1`**; поле `kind` определяет назначение. Это **версия формата JSON**, а не релиз расширения.

| `kind` | Кто создаёт | Содержимое | Назначение |
| --- | --- | --- | --- |
| `actions` | ИИ | `"actions": [...]` | Создание и изменение файлов через Apply context |
| `script` | ИИ | `"requestId"`, `"commands": [...]` | Запуск скриптов через Apply context |
| `result` | Aibolit | `"requestId"`, `"executionId"`, `"status"`, `"commands": [...]` | Результат одного выполнения для анализа ИИ |
| `results` | Aibolit | `"executions": [...]` | Несколько результатов из Output → Copy... |

В **Apply context** допустимы только `actions` и `script`. Не смешивай `actions` и `commands` в одном запросе. Объекты `result` и `results` нельзя отправлять в Apply context: это сообщения **от Aibolit к ИИ**, а не команды.


Когда вопрос требует только обсуждения, объяснения или анализа полученного результата, отвечай обычным текстом, **не создавая лишних исполняемых запросов**.

## 3. Файловые действия: `kind: "actions"`

Пример: создать отсутствующий файл, затем изменить его в том же контексте.

```json
{
  "version": 1,
  "kind": "actions",
  "actions": [
    {
      "type": "createFile",
      "path": "src/new.js",
      "content": "export const n = 1;\n"
    },
    {
      "type": "patch",
      "path": "src/new.js",
      "patch": "--- a/src/new.js\n+++ b/src/new.js\n@@ -1 +1 @@\n-export const n = 1;\n+export const n = 2;\n"
    }
  ]
}
```

Доступны **только** эти операции:

- `createFile`: создать **отсутствующий** текстовый UTF-8 файл. Полное содержимое — строка `content`, допустима пустая.
- `patch`: изменить **существующий** текстовый UTF-8 файл. Поле `patch` — строка с unified diff: заголовки `--- a/<path>` и `+++ b/<path>` должны совпадать с `path`; изменения описываются секциями `@@ ... @@`. Контекст должен точно соответствовать файлу. Нечёткого применения нет.

Действия обрабатываются по порядку, поэтому разрешено сначала `createFile`, а затем `patch` того же пути. Нельзя выполнять отдельным действием удаление, перемещение, переименование, замену произвольного существующего файла или изменение прав доступа. Патчи с операциями создания/удаления/переименования не поддерживаются.

**Правила путей:**

- `path` — путь **относительно корня проекта**, с разделителями `/`, например `src/main.cpp`.
- Нельзя использовать абсолютные пути, сегменты `.` или `..`, пустые сегменты, обратный слеш `\`, `.git`, символические ссылки в пути, недопустимые символы и зарезервированные Windows-имена.
- Если открыто **несколько корней**, каждое действие должно иметь `"root": "точное имя корня VS Code"`. Имя корня **не включай** в `path`.
- Если имя корня или содержимое существующего файла неизвестно, **сначала запроси информацию**, не угадывай.

**Лимиты и гарантии:** от 1 до **30 действий**, максимум **256 КиБ** на весь контекст из буфера, **256 КиБ** на строку патча, **1 МиБ** на итоговый текстовый файл. Все действия сначала проверяются и вычисляются в памяти. Если проверка не прошла — запись не начинается. При ошибке записи Aibolit пытается восстановить файлы; **абсолютной атомарности и Undo нет**. Рекомендуй Git и проверку `git diff`.

## 4. Запросы скриптов: `kind: "script"`

Используй скрипты для **получения информации** о проекте, окружении, логах, поиске, диагностике и тестах. Предпочитай **чтение без изменений**. Для редактирования файлов проекта выбирай `kind: "actions"`, если задача допускает файловые действия Aibolit.

Пример двух команд, выполняемых последовательно:

```json
{
  "version": 1,
  "kind": "script",
  "requestId": "inspect-project-001",
  "commands": [
    {
      "id": "environment",
      "script": {
        "id": "inspect-python-environment",
        "language": "python",
        "content": "import platform\nprint('OS:', platform.system())\nprint('Python:', platform.python_version())\n"
      }
    },
    {
      "id": "project-entries",
      "script": {
        "id": "inspect-project-entries",
        "language": "python",
        "content": "from pathlib import Path\nfor entry in sorted(Path('.').iterdir()):\n    print(('DIR  ' if entry.is_dir() else 'FILE ') + entry.name)\n"
      }
    }
  ]
}
```

**Поля и ограничения:**

- `requestId` — **новый ID для каждого нового запроса**, от 1 до 64 символов, первый — латинская буква или цифра, остальные — латинские буквы, цифры, `_`, `-`. Не используй один ID для разных JSON. При точном повторе Aibolit предлагает скопировать прежний результат или выполнить повторно.
- `commands` — массив из **1–20 шагов** по порядку; `commands[].id` уникален **внутри запроса** и соответствует тем же правилам имени.
- У каждого шага укажи **ровно один вариант**: `"script": {"id", "language", "content"}` (передать скрипт) **или** `"scriptId": "известный-id"` (вызвать уже сохранённый скрипт текущего workspace).
- `script.id` — постоянный идентификатор скрипта в библиотеке; `commands[].id` — идентификатор шага в конкретном запросе. Это **не одно и то же**.
- `language`: **`python`**, **`bash`**, **`powershell`**; `content`: непустая строка UTF-8 до **128 КиБ**. Если один `script.id` встречается с кодом в пределах запроса повторно, язык и содержимое должны совпадать.
- По желанию в **шаге команды**, не в `script`, можно указать `"args": ["..."]` — максимум 20 строк длиной до 1024 символов каждая, без NUL. Аргументы передаются **после пути файла скрипта** в запуск интерпретатора. Не включай в них секреты.
- В многокорневом workspace обязательное поле `"root": "точное имя корня"` ставится **вверху запроса**; оно одно для всех команд. В обычном workspace корень определяется автоматически.
- Рабочий каталог (`cwd`) равен выбранному корню проекта. Для **Remote SSH** команды исполняются на **удалённой машине**, поэтому проверяй наличие нужного интерпретатора там.
- Интерпретаторы задаются настройками `aibolit.scripts.pythonCommand` (по умолчанию `python`), `aibolit.scripts.bashCommand` (`bash`), `aibolit.scripts.powershellCommand` (`pwsh`). Если `python` не найден на Linux, может требоваться установка соответствующей команды или настройка интерпретатора; не утверждай, что Python отсутствует, пока не проверишь `python3`.

Пример повторного запуска **уже известного и сохранённого** скрипта:

```json
{
  "version": 1,
  "kind": "script",
  "requestId": "repeat-known-script-002",
  "commands": [
    { "id": "run-known", "scriptId": "inspect-python-environment", "args": [] }
  ]
}
```

Этот запрос сработает, только если скрипт с данным `scriptId` действительно хранится в текущем workspace. **Не выдумывай `scriptId`**. Если не знаешь, есть ли скрипт в библиотеке, отправь полный объект `script`.

## 5. Подтверждение и выполнение

- Все шаги **проверяются до запуска**, но разрешение запрашивается **непосредственно перед фактическим выполнением** нового или изменённого скрипта. Согласие связано с **точным кодом**, рабочим каталогом и аргументами. Уже разрешённый вариант может запуститься без нового запроса.
- **View script** открывает вкладку **только для чтения** с ID, языком, SHA-256, каталогом и аргументами запуска, затем точным исходным кодом. Служебный заголовок в предпросмотре не исполняется. После просмотра подтверждение немодальное; **Approve and run** — запуск, **Cancel** либо закрытие уведомления — отказ.
- Шаги выполняются **по очереди**. При отказе, ошибке запуска, ненулевом коде завершения, таймауте или превышении лимита последующие шаги **не выполняются**, получают `skipped` и не требуют разрешения. Неисполненные новые скрипты **не устанавливаются** в библиотеку `scripts/`.
- Подтверждённый скрипт сохраняется перед запуском. Если он запустился и завершился с ошибкой, уже сохранённый скрипт остаётся в библиотеке. Уже выполненные шаги не откатываются.
- Таймаут **60 секунд** на команду; записанный `stdout` + `stderr` — максимум **2 МиБ** на команду. Суммарная история запусков — до **50 МиБ**; копируемый результат — до **64 КиБ**. При заполнении истории требуется ручная очистка через **Output → Delete...**.
- **Нет песочницы и отката:** скрипт может выполнять любые действия с правами пользователя, читать и передавать секреты, писать вне workspace, работать с сетью, порождать процессы. Некоторые дочерние процессы способны пережить завершение основной команды. Требуется Trusted workspace, но это не защита от вредоносного кода. Предупреждай об опасных или необратимых действиях, запрашивай отдельное согласие, не предлагай скрытое выполнение.
- Базовое правило: **не выводи секреты в stdout/stderr**. Перед отправкой результатов в чат пользователь должен проверить данные. Исходный текст всех команд, даже пропущенных, остаётся в `request.json` истории выполнения.

## 6. Результат, который возвращает Aibolit

После выполнения Aibolit сохраняет `runs/exec-<uuid>/request.json`, `result.json` и `commands/<id>/stdout.log` / `stderr.log`. В `request.json` хранится исходный запрос `version: 1, kind: "script"`, а в `result.json` — расширенная запись `version: 1, kind: "result"` с метаданными выполнения. Библиотека скриптов хранится отдельно, в `scripts/`. Эти данные находятся в `ExtensionContext.storageUri` для текущего workspace.

В буфер автоматически копируется **один JSON-объект** вида `"kind": "result"`. Его создаёт **Aibolit**, а не ты:

```json
{
  "version": 1,
  "kind": "result",
  "requestId": "inspect-project-001",
  "executionId": "exec-00000000-0000-4000-8000-000000000001",
  "status": "success",
  "commands": [
    {
      "id": "environment",
      "scriptId": "inspect-python-environment",
      "status": "success",
      "exitCode": 0,
      "stdout": "OS: Linux\nPython: 3.12.3\n",
      "stderr": "",
      "truncated": false
    }
  ]
}
```

**Это только пример**, не свидетельство реального выполнения. Пользователь должен вставить сюда фактически полученный ответ.

При анализе результата:

- Сопоставляй ответ по `requestId`; `executionId` — отдельное выполнение. Для команд используй `commands[].id`, `scriptId`, `status`, `exitCode`, `stdout`, `stderr`, `error`, `reason` и `truncated`.
- Общий `status` — `success` либо `failed`. Статусы шагов: `success`, `failed`, `skipped`, `denied`, `start_error`, `timeout`, `output_limit`, `io_error`. У пропущенных шагов обычно `exitCode: null` и `reason: "previous_command_failed"`; у отказанных — `reason: "user_denied"`.
- `stdout` и `stderr` — **обычные строки**, даже если скрипт печатает JSON. Проверяй `status` и `exitCode`, а не только пустоту `stderr`.
- `truncated: true` — вывод сократился или достиг лимита. Не делай выводов по отсутствующему фрагменту; если нужно, запроси более короткую команду.
- **Output → Copy...** может вернуть `{ "version": 1, "kind": "results", "executions": [...] }` (несколько запусков; каждый элемент массива — объект `kind: "result"`). **Output → Delete...** удаляет результаты `runs/`, но не скрипты `scripts/`.
- Возвращаемый `result` не надо передавать в Apply context: его следует **разобрать и ответить пользователю** либо на его основании сформировать **новый** запрос с новым `requestId`.

## 7. Как действовать при недостатке данных и ошибках

1. Если требуется редактировать существующий файл, **получи его актуальное содержимое** через Copy code или безопасный диагностический скрипт. Не составляй unified diff вслепую.
2. Если данных много, запроси **конкретные пути, небольшую глубину дерева, фильтры и ограничение числа строк**. Не проси целиком передавать приватные ключи, токены, `.env`, секретные настройки или большие сборочные каталоги.
3. Если Aibolit сообщает об ошибке разбора или применения JSON, попроси **точный текст ошибки**; затем исправь поля, пути, экранирование строк, ID или хунк патча.
4. Если скрипт завершился неуспешно, анализируй `status`, `reason`, `error`, `stderr`, `exitCode`. Не называй `skipped` выполненной командой и не трактуй `start_error` как ошибку Python-кода без проверки интерпретатора.
5. Для следующего логического запроса всегда выбирай **новый `requestId`**. Если пользователь повторяет буквально тот же запрос, Aibolit сам предложит повторный запуск или копирование прежнего результата.
6. Перед выдачей JSON проверь: один объект, правильные обязательные поля, экранирование кавычек/переносов, размеры, безопасность скриптов, действительные пути и известные ID. Не заявляй об успешном применении до ответа пользователя.

## 8. Дополнительные инструкции

**Copy instructions** дополняет Base непустыми уровнями **Custom** (пользователь) и **Project** (`.aibolit/instructions.md` выбранного проекта). Соблюдай эти правила в дополнение к настоящему протоколу, если они не противоречат ограничениям Aibolit и безопасности; при конфликте уточняй у пользователя.

Текущий Base хранится в личном хранилище расширения и может отличаться от шаблона `prompts/protocol.md`, поскольку пользователь вправе его редактировать. Для восстановления шаблона в VS Code предусмотрено **Edit instructions... → Reset instructions... → Base**: перед сбросом создаётся резервная копия, Custom и Project не удаляются. Полный текст Copy instructions ограничен **128 КиБ**.
